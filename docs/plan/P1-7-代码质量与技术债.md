## 1. Clippy 警告清零 🔴

### 1.1 if_same_then_else（oc-core/src/config.rs:87）

**现状**：
```rust
} else if m.contains("gpt-4o") || m.contains("gpt-4.1") || m.contains("o1") || m.contains("o3") {
    128_000
} else if m.contains("gpt-4-turbo") || m.contains("gpt-4-1106") {
    128_000  // ← 与上一分支完全相同
```

**修法**：合并分支
```rust
} else if m.contains("gpt-4o") || m.contains("gpt-4.1") || m.contains("o1") 
       || m.contains("o3") || m.contains("gpt-4-turbo") || m.contains("gpt-4-1106") {
    128_000
```

**成本**：5 分钟  
**验收**：`cargo clippy -p oc-core` 无此警告

### 1.2 while_let_loop（oc-llm/src/sse.rs:25）

**现状**：
```rust
loop {
    let Some(pos) = self.buf.find('\n') else { break };
    // ...
}
```

**修法**：改用 `while let`（更惯用）
```rust
while let Some(pos) = self.buf.find('\n') {
    let line = self.buf[..pos].trim_end_matches('\r').to_string();
    self.buf.drain(..=pos);
    if line.is_empty() { continue; }
    // ...
}
```

**成本**：5 分钟  
**验收**：`cargo clippy -p oc-llm` 无此警告

### 1.3 should_implement_trait（oc-store/src/types.rs，3 处）

**现状**：`Role::from_str` / `Tier::from_str` / `Origin::from_str` 被警告应实现 `std::str::FromStr`

**修法**：实现标准 trait
```rust
impl std::str::FromStr for Role {
    type Err = String;  // 或定义专用 ParseError
    fn from_str(s: &str) -> Result<Self, Self::Err> {
        match s {
            "assistant" => Ok(Role::Assistant),
            "tool" => Ok(Role::Tool),
            "user" => Ok(Role::User),
            "system" => Ok(Role::System),
            _ => Err(format!("unknown role: {}", s)),
        }
    }
}
// Tier / Origin 同理
```

**调用方改动**：`Role::from_str(s)` → `s.parse::<Role>()?`（更惯用）

**成本**：30 分钟（3 个类型 + 调用方迁移 + 回归测试）  
**验收**：`cargo clippy -p oc-store` 无此警告

## 2. TODO 标记归档 🟡

### 2.1 registry 空闲淘汰（oc-server/src/registry.rs:9）

**现状**：
```rust
//! **不做空闲淘汰**：单用户短期无碍；长期可加 LRU/TTL（留 TODO）。
```

**分析**：
- P2 已有"会话 actor 空闲淘汰"项（与此同源）
- IdempotencyCache 同样无 TTL/LRU（P2 另有一项）
- 两者应**一起做**（同类内存泄漏防护）

**修法**：
1. 确认 P2 清单已覆盖（已有"idem 幂等缓存 TTL/LRU"+"会话 actor 空闲淘汰"）
2. 将此注释改为：
   ```rust
   //! **无空闲淘汰**：单用户场景下会话数可控。生产化前需配合 IdempotencyCache
   //! 一起加 TTL/LRU（见 P2 计划：idem 缓存 TTL + 会话淘汰）。
   ```
3. 或直接删除此行（P2 清单已明确，不需代码里再留 TODO）

**成本**：5 分钟  
**验收**：全仓 `rg TODO` 无此条；P2 计划已覆盖

## 3. 错误处理一致性（可选优化）🟢

**观察**：
- `oc-core::agent` 用裸 `String` 作错误（`Failed(String)`）
- `oc-store` 有专用 `StoreError` 枚举
- 部分地方 `unwrap_or(0)` 静默吞错（`ops.rs:15` 的 `now_millis()`）

**建议**（非强制）：
- core 层统一用结构化错误枚举（`CoreError::ModelTimeout` / `CoreError::ToolFailed{name, reason}`），
  避免字符串拼接 + 便于上层分类处理
- `now_millis()` 的 `unwrap_or(0)` 可改为 `expect("system time before epoch")`——真发生是致命问题，
  不该静默返回 1970-01-01

**成本**：2-3 天（涉及多处调用方）  
**优先级**：低；不阻塞 P2，可在 P2 过程中渐进重构

## 4. 命名与注释清理（可选优化）🟢

### 4.1 测试命名风格
**观察**：测试名混用蛇形与描述式
- 好例子：`abort_interrupts_pending_approval_and_cleans_registry`（行为描述清晰）
- 可改进：部分测试名过短（如 `roundtrip`）不表意

**建议**：统一为"行为描述式"（`should_*` / `行为_when_条件`）

### 4.2 注释覆盖
**观察**：
- 模块顶部注释完善（引用设计文档节号，如"设计 §4.2"）
- 公开函数多数有文档注释
- 部分复杂逻辑缺少注释（如 P1-5 cron 的"先跑后重排"逻辑，注释在计划文档里但代码里没说）

**建议**：把**反直觉决策**的 rationale 写进代码注释，不要只放计划文档
```rust
// 重复任务保持【先跑后重排】（不是先重排再跑）：
// 若先占位后跑，进程中途被杀会把 next_at 永久留空 → 每日提醒从此不触发。
// 先跑后排虽可能重复提醒一次（被杀后重启），但比永久失效糟得少。
exec_prompt(&prompt).await?;
cron_reschedule(id, next_fire)?;  // ← 顺序不能反
```

**成本**：1-2 天  
**优先级**：低；可在日常维护中渐进改进
