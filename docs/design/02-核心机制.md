## 1. 整体架构与进程模型

```
                         ┌───────────────────────────────────────┐
   Channels (in)         │              GATEWAY (单进程守护)         │
   WhatsApp/Telegram ───►│  渠道连接  ─►  入站归一化  ─►  路由(bindings)│
   Slack/Discord/...     │                        │                 │
                         │                        ▼                 │
   Control clients       │              Agent Runtime (per-session) │
   CLI/WebUI/macOS ─WS──►│   队列车道 ─► 上下文组装 ─► LLM ─► 工具 ─► 流式│
   iOS/Android node ─WS─►│                        │                 │
                         │                        ▼                 │
                         │        SQLite (state DB + per-agent DB)  │
                         └───────────────────────────────────────┘
                                          ▲
                              出站回复 / 流式 event 回渠道 & 客户端
```

**关键不变量（invariants）：**
- 每主机**恰好一个** Gateway，是唯一开启渠道会话（如 WhatsApp Baileys）的地方 → 需要"网关锁"。
- 所有会话状态归 Gateway 所有；UI 客户端只查询，不本地持有真相。
- 握手强制：非 JSON 或非 `connect` 首帧 → 硬断开。
- 事件不重放；客户端遇 gap 必须刷新。

**→ Rust 建议**：单二进制，tokio 多任务 runtime。Gateway 是一个持有共享状态（`Arc`）的 actor 集合：渠道 actor、连接 actor、会话 lane 调度器、SQLite 写队列 actor。网关锁用文件锁（`fs2` / advisory lock）+ 端口绑定双保险。

## 2. Gateway WebSocket 协议

### 帧结构
- 请求：`{type:"req", id, method, params}`
- 响应：`{type:"res", id, ok, payload|error}`
- 事件：`{type:"event", event, payload, seq?, stateVersion?}`
- 错误：`{code, message, details?, retryable?, retryAfterMs?}`，客户端按 `code`/`details.code` 分支，`message` 仅供人读。

### 握手流程
1. Gateway 先推 `connect.challenge`（含 `nonce`, `ts`）。
2. 客户端回 `connect`：带 `minProtocol/maxProtocol`、`client{id,version,platform,mode}`、`role`、`scopes`、`caps`、`auth{token|password}`、`device{id,publicKey,signature,signedAt,nonce}`。
3. Gateway 回 `hello-ok`：`protocol`、`server{version,connId}`、`features{methods,events}`、`snapshot`（presence+health）、`auth{role,scopes,deviceToken?}`、`policy{maxPayload,maxBufferedBytes,tickIntervalMs}`。

### 鉴权与信任
- 模式 `none/token/password/trusted-proxy`。identity-bearing 模式（Tailscale Serve / 非 loopback trusted-proxy）从请求头满足鉴权。
- 所有 connect 必须签名 `connect.challenge` nonce；签名 payload v3 绑定 platform+deviceFamily。
- 设备配对：新 device id 需批准，之后发 device token；本地 loopback 可自动批准；tailnet/LAN 即使同主机也算 remote，需批准。
- 幂等键：side-effecting 方法（`send`/`agent`）必须带，短期去重缓存。

### 角色与 scope
- 角色：`operator`（控制面）/ `node`（能力主机）/ `worker`（云执行，封闭协议）。
- Operator scope 封闭集：`operator.read/write/admin/approvals/pairing/talk.secrets`。
- 保留前缀强制 admin：`config.*` `exec.approvals.*` `wizard.*` `update.*`。
- 广播事件按 scope 过滤（chat/agent/tool 需 `operator.read`），每连接独立 seq 保序。

### 版本
- 当前 v4；node 可用 N-1（v3）。协议由 TypeBox schema 定义，生成 JSON Schema，再生成 Swift model。

**→ Rust 建议**：用 `tokio-tungstenite`。协议类型用 `serde` + 一套 enum tagged union（对应 TypeBox 判别联合）。scope 检查做成中间件层。幂等缓存用带 TTL 的 `DashMap` 或 `moka`。schema 可用 `schemars` 生成 JSON Schema 供跨语言客户端。每连接维护独立递增 seq。

## 3. 智能体运行循环（Agent Loop）

一次 run 把一条消息变成动作与回复，阶段：**intake → 上下文组装 → 模型推理 → 工具执行 → 流式 → 持久化**。

序列：
1. `agent` RPC 校验参数、解析会话（sessionKey/sessionId）、持久化会话元数据，**立即返回** `{runId, acceptedAt}`。
2. `agentCommand` 跑这一轮：解析模型 + thinking/verbose/trace 默认、加载 skills 快照、调 `runEmbeddedAgent`，若嵌入循环没发终态则补发 lifecycle end/error。
3. `runEmbeddedAgent`：经**每会话队列 + 全局队列**串行化；解析模型 + auth profile；构建会话；订阅运行时事件；流式 assistant/tool delta；执行 run 超时（到期 abort）；返回 payload + usage。
4. `subscribeEmbeddedAgentSession` 把运行时事件桥接成三条流：`tool` / `assistant` / `lifecycle`（phase start|end|error）。
5. `agent.wait` 只等 lifecycle end/error（默认 30s），**不停止底层 run**。

**回复整形**：assistant 文本 + 可选 reasoning + inline 工具摘要（verbose 且允许时）。`NO_REPLY` 静默 token 被过滤；messaging 工具重复发送被去重；无可渲染 payload 且有工具报错则补发 fallback 错误回复。

**结束点**：agent 超时（abort）、AbortSignal（cancel）、Gateway 断连 / RPC 超时、agent.wait 超时（仅等待）。

**→ Rust 建议**：一次 run 是一个 tokio task，返回 `runId` 后 detach。三条流用 `tokio::sync::broadcast` 或 `mpsc` + 订阅。超时用 `tokio::time::timeout` + `CancellationToken`。终态归一化单独一个模块（对应 `agent-run-terminal-outcome.ts`），不要在各投影里重推 timeout/cancel 优先级。

## 4. 队列与并发（车道模型）

OpenClaw 用一个**车道感知 FIFO 队列**串行化入站 auto-reply run：
- 每会话车道 `session:<key>`：并发上限 1，保证一个会话同时只有一个活跃 run。
- 全局车道（默认 `main`）：`min(16, max(8, CPU 并行度))`；`subagent` 默认 8；未配置车道默认 1。
- 额外车道：`cron` / `cron-nested` / `nested` / `subagent`，让后台任务并行而不阻塞入站回复。

### 队列模式（`/queue`）
- `steer`（默认）：把中途到达的消息注入活跃 run——**在当前 assistant 轮执行完工具调用后、下次 LLM 调用前**投递所有待转向消息。若 run 未在流式或不支持转向，则等 run 结束再作为新 prompt。
- `followup`：不转向，排队为 run 结束后的下一轮。
- `collect`：合并静默窗后为**单个** followup 轮。
- `interrupt`：中止当前 run，跑最新消息。

选项：`debounceMs`（默认 500）、`cap`（默认 20）、`drop`（summarize/old/new，默认 summarize）。

排队轮取消：Gateway 为排队中的 client runId 保留 cancel identity；`chat.abort` 先取消已授权排队轮，再中止活跃 run。

**→ Rust 建议**：一个 `LaneScheduler`：`HashMap<LaneId, Lane>`，每 lane 一个带并发信号量（`tokio::sync::Semaphore`）的有序队列。会话车道信号量 permit=1。steer 注入用每 run 一个 `mpsc` steer channel，在工具执行边界 drain。debounce 用 `tokio::time` 定时器。纯异步、无后台 worker 线程（原实现也是纯 promise）。

## 5. 会话路由与生命周期

### 路由
| 来源 | 行为 |
|---|---|
| DM | 默认共享会话（main） |
| 群 | 按群隔离 |
| room/channel | 按 room 隔离 |
| cron | 每次新会话 |
| webhook | 按 hook 隔离 |

DM scope：`main / per-peer / per-channel-peer / per-account-channel-peer`。多用户必须开隔离，否则串号。
多 agent：bindings（channel, accountId, peer）→ agentId，**最具体优先**（exact peer > parent peer > peer wildcard > guild+roles > guild > team > account > channel > default）。同 tier 第一个匹配胜；多字段 AND。

### 生命周期
- 会话默认不自动重置（`mode:none`），compaction 管理增长的上下文。
- `daily`（配置本地小时，默认 4 点，基于 sessionId 起始时间）/ `idle`（基于最后真实交互）/ 手动 `/new` `/reset`。
- 三个时间戳：`sessionStartedAt`（daily 用）/ `lastInteractionAt`（idle 用）/ `updatedAt`（列表/剪枝用，非权威）。heartbeat/cron/exec 系统轮写元数据但**不**延长 daily/idle 新鲜度。

**Transcript 写锁 + 代际校验**：每次 append/rewrite 在同步提交事务内校验当前会话身份，stale run 不能覆盖新代。任何 rewrite/compaction/truncation 都要先拿同一把锁。

**→ Rust 建议**：会话 key 是结构化枚举，路由是纯函数。bindings 匹配做成有序规则列表 + 打分。写锁用 per-session `tokio::sync::Mutex` + DB 内代际字段（compare-and-swap）。

## 6. 上下文组装与系统提示词

三层组装：
- `buildAgentSystemPrompt`：纯渲染器，从显式输入渲染，不直接读全局 config。
- `resolveAgentSystemPromptConfig`：解析 config 驱动的旋钮（owner 显示、TTS 提示、别名、记忆引用模式、委派模式）。
- 运行时适配器（embedded/CLI/预览/compaction）：收集实时事实（工具、沙箱状态、渠道能力、上下文文件、provider prompt 贡献）调 facade。

**Prompt cache 边界**：大块稳定内容（含 Project Context）放缓存边界**之上**；易变的每轮段（Messaging/Voice/Group Chat/Reactions/Heartbeats/Runtime）放**之下**，让本地 prefix cache 复用稳定前缀。

**Bootstrap 注入**：AGENTS.md / SOUL.md / IDENTITY.md / USER.md / BOOTSTRAP.md（仅新工作区）/ MEMORY.md。字符预算：单文件 `bootstrapMaxChars`（20000）、总 `bootstrapTotalMaxChars`（60000），超出截断带 marker（文件本身不丢）。子智能体只注入 AGENTS.md。

**Skills 注入**：`<available_skills>` 列表含 file path + `<version>sha256:...>`，模型用 `read` 按需加载 SKILL.md，version 变了要重读。

**Prompt mode**：`full`（默认）/ `minimal`（子智能体，省去记忆/自更新/别名/身份等）/ `none`（仅身份行）。

**上下文引擎**（可插拔）四生命周期：`ingest`（新消息入库）/ `assemble`（每次 run 前返回有序消息 + 可选 systemPromptAddition + estimatedTokens）/ `compact`（满或 /compact）/ `afterTurn`。内置 `legacy` 引擎：ingest/afterTurn 无操作，assemble pass-through，compact 委派内置摘要。`ownsCompaction` 决定是否禁用内置自动压缩。引擎故障被隔离（quarantine）并降级到 legacy，不让 agent 哑掉。

**→ Rust 建议**：prompt 渲染器保持纯函数（输入 → String），便于快照测试。缓存边界用两个明确 buffer（stable / volatile）拼接。上下文引擎做成 trait，legacy 是默认实现。token 估计用 `tiktoken-rs` 或按 provider 的 tokenizer。

## 7. 压缩（Compaction）与剪枝

- 触发：近上限自动触发，或模型返回 overflow 错误（识别几十种 provider 错误串）→ 压缩后重试。
- 机制：旧对话摘要成一条 compact 条目存进 transcript；保留近期消息；保持 tool_call 与 tool_result 成对（split point 落在工具块内则移动边界）。完整历史仍在盘上，压缩只改模型下轮所见。
- 手动 `/compact [指示]`，用 `keepRecentTokens`（默认 20000）作为 cut-point 预算。
- 压缩模型：默认用会话主模型；可设独立/更强/本地模型；失败可走会话 fallback 链（临时，不写回）。
- 压缩前**记忆 flush**：静默一轮把要点写盘防丢。
- safeguard 模式（新配置默认）：更严 + 摘要质量审计；设 provider 强制 safeguard。
- **剪枝 vs 压缩**：剪枝只裁旧工具结果、内存内、不落盘、每请求生效；压缩摘要整段对话并落盘。

**→ Rust 建议**：overflow 错误识别做成一张模式表（provider → 正则集）。压缩是一个特殊的内部 agent 轮（可用不同模型）。split-point 算法要保证工具块配对——单独单元测试。

## 8. LLM / Provider / 模型运行时代际

- Provider 抽象负责传输 + 流式解析；覆盖 OpenAI 兼容 + Anthropic 兼容端点即覆盖大多数。
- Auth profile per-agent（api_key / token / OAuth）；次级 agent OAuth 过期可读穿到主 agent 同 profile 取最新 token。
- 模型目录 + 能力族（capability family）；别名、`/model` 切换、per-session 覆盖。
- **Failover 链**：provider 报可 fallback 错误时切下一个模型。
- **Retry**：含 overflow → 压缩再试。
- **超时**：模型空闲看门狗 cloud 120s / 自托管 300s（`timeoutSeconds` 可延长，但受更低的 agent 超时约束）；agent runtime 默认 48h（0=无限）。
- **模型运行时代际（关键性能机制）**：Gateway 启动 + config/plugin/auth 发布时，为每个配置的 agent 构建**一份预备好的模型运行时代际**——发现的 auth 模板、模型注册表、投影的模型目录作为**一个原子快照**。agent run 从快照 fork 可变 auth/registry；status/cron/doctor/TUI/PDF/image 路径直接读已发布目录，**不重复文件系统发现**。失败/陈旧代际绝不与更新的部分代际并存。

**→ Rust 建议**：Provider 是 trait（`stream(request) -> impl Stream<Delta>`）。代际快照用 `Arc<ModelRuntimeGeneration>`，`ArcSwap` 原子替换发布，run 持有克隆的 `Arc`。这是 Rust 相对 TS 的巨大优势：零成本共享 + 无 GC。流式解析用 SSE 解析器 + `futures::Stream`。

## 9. 工具执行、策略与审批

- 工具是模型看到的 typed function 定义。**策略在模型调用前就过滤**：active profile → allow/deny → provider 限制 → sandbox 状态 → channel 权限 → plugin 可用性。被移除的工具其 schema 不发给模型。
- before/after tool-call 适配器 + hook 可拦改参数/结果。工具结果按大小/图片净化后再记录/发出。
- **Exec 审批**：危险命令触发 `exec.approval.requested` 广播，operator 用 `exec.approval.resolve`（需 `operator.approvals`）；渠道原生审批卡优先，否则 `/approve`。node 目标的 exec 请求必须带 `systemRunPlan`（canonical argv/cwd/rawCommand/session），prepare 与最终 forward 之间若被篡改则拒绝。
- **权限模式** + **沙箱**（docker/ssh/openshell；mode off/non-main/all；scope agent/session/shared；默认 off）。Gateway 进程永远在宿主，只有工具执行进沙箱。**Elevated exec** 受控跳出沙箱。
- client capabilities（`tool-events`/`inline-widgets`）：工具可声明所需 capability，渠道来源的 run 无 client capability 故 capability-gated 工具不可用（即使策略允许）。

**→ Rust 建议**：Tool 是 trait（`schema()` + `invoke(args, ctx) -> Result`）。策略过滤是一条纯函数管道，返回"本轮有效工具集"。审批用 gateway 广播 + `oneshot` 等待决定 + 持久审批注册表（SQLite，first-answer-wins）。沙箱后端也是 trait；docker 用 `bollard`。

## 10. 记忆架构（分层 + provenance + dreaming）

**五条设计原则**：无隐藏状态（只记文件里写的）；写路径是难点也是安全边界；确定性门控 + 门内用模型判断；记忆失败绝不阻塞回复（超时/fallback）。

**分层**（curated core 与 episodic 之间是最重要的边界）：
| Tier | 载体 | 写入者 | 注入 |
|---|---|---|---|
| Instructions | AGENTS.md 等 | 仅人 | 每次会话起始 |
| Curated core | MEMORY.md, USER.md | dreaming 巩固 / 用户显式请求 | 会话起始，有预算 |
| Episodic | memory/YYYY-MM-DD.md, transcripts | agent 工作时 / flush / 转写 | 从不；按需搜索 |
| Prospective | standing intents(SQLite) + cron | intent 工具 / 调度 | 仅触发时 |
| Review | DREAMS.md | dreaming | 从不；给人读 |

**Provenance（抗投毒核心）**：每条记忆带 SQLite 列（模型无法用 prose 伪造）：
- Origin class 封闭集：`owner`（受信渠道内 owner 键入）/ `agent`（agent 从 owner 内容派生）/ `untrusted`（外部内容派生）/ `system`（脚手架）。无法判定则保守归 untrusted/system，**绝不默认 owner**。
- Session kind（interactive/cron/heartbeat/subagent）；cron/heartbeat/subagent 会话**不产生**持久记忆候选。
- 防召回环：从记忆注入进上下文的内容被结构性标记，**不再被重新抽取**。

**召回两 lane**：
- Lane 1（默认，零模型调用）：bootstrap 注入 + 排名搜索（相关性 × 30 天半衰期时间衰减 × importance 1-10）+ trigger 注入（词法/向量预筛，≥0.72 命中，≤3/轮）。**自动注入仅限 curated tier**（daily notes/transcripts 永不自动注入——安全属性）。
- Lane 2（升级）：真子智能体跨历史检索，仅当消息显示召回意图且 Lane 1 无强命中时触发。

**Dreaming**：后台三阶段（light/REM 暂存+反思、deep 双门升级）。deep 门：确定性门（加权信号排名 + 结构性排除 untrusted/system）→ 巩固步（模型轮重写 MEMORY.md，去重/supersede/紧凑）。写安全用乐观并发（内容 hash 重校验 + 原子 rename），失败回退 append-only。

**→ Rust 建议**：provenance 是不可变枚举 + SQLite 列，写入端分类，读取端信任。Lane 1 完全无模型调用（纯 SQL + 向量），是延迟敏感路径——用 `sqlite-vec` 或 LanceDB。每步都有 `tokio::time::timeout` + fallback。记忆后端做成 trait（单槽，同时只一个生效）。

## 11. 存储：SQLite 单一真相

**硬规定**：SQLite 是唯一运行时状态存储，**不用** JSON/JSONL/TXT sidecar 存 OpenClaw 拥有的运行时状态/缓存/队列/注册表/索引/游标/checkpoint。文件存储仅限命名产物（导入导出/附件/日志/备份/外部工具契约）。

**两个库**：
- 共享 state DB `state/openclaw.sqlite`：共享配置状态、注册表、审批、plugin KV、共享运行时状态。
- per-agent DB `agents/<id>/agent/openclaw-agent.sqlite`：会话、transcript、记忆索引、auth 状态、会话状态、agent 级运行时状态。
- 少量高量/生命周期特殊的用专用 DB（task registry、trajectory）。
- quarantine 决策存独立 `openclaw-quarantine.sqlite`（在被隔离库损坏时仍存活）。

**版本化**：`PRAGMA user_version` + `schema_meta` 行（role/agent_id/schema_version/app_version）。打开旧库前向迁移；拒绝比运行 build 新的 schema（报 `newer schema version`）。当前 state schema 6 / agent schema 16（package.json 声明）。纯增列（新表，旧 reader 能容忍）**不 bump** 版本，用一次性幂等 lazy ensure。bump 需显式用户同意。

**事务规则（关键正确性+性能）**：写事务是**同步提交段**——async 规划、文件访问、plugin hook、predicate 都在 `BEGIN` 前完成；然后重读校验权威行再写。**事务回调里绝不 return Promise 或 await**。

访问用 Kysely helper（非裸 SQL 字符串），除 DDL/迁移/bootstrap/窄化原语。

**完整性检查**：每次打开校验 schema_meta；迁移前全量 integrity+FK+role+schema+index 扫描；后台校验约每日一次；doctor/backup/compaction 前全扫。

**→ Rust 建议**：用 `rusqlite`（同步、性能好、贴合"同步提交事务"约束）或 `sqlx`（异步但要小心事务边界）。推荐 **rusqlite + 专用写线程/actor**（对应 SQLite writer queue）：写请求经 channel 送到单写线程，读用连接池（WAL 模式并发读）。schema 迁移用嵌入式 SQL + 版本表。STRICT 表 + WAL + `synchronous=NORMAL`。这是 Rust 相对 Node 的另一大性能优势。

## 12. 配置、Secrets 与迁移

- **单一规范**：运行时只读当前 config shape，不做旧 key 静默兼容。config schema 由类型 + schema/help + metadata + baselines + docs 对齐。
- config 破坏必须配套 `openclaw doctor --fix` 迁移（检测旧 shape → 解释 → 备份 → 重写为规范）。核心/auth config 在核心 doctor；plugin config 在该 plugin 的 doctor 契约。
- **env 高门槛**：加 config/env 前先证明现有行为/provider 选择/默认/doctor 迁移都解决不了；优先删/合并。
- **Secrets/SecretRef**：channel/provider 凭据在 `~/.openclaw/credentials/`；model auth profile 在 per-agent DB。SecretRef 失败隔离到最小 owning surface，未知归属 fail-closed；Gateway 仅当自身 ingress 保护建立不了 / config 结构无效 / owning surface 未知时才拒绝启动，否则启动并标记该能力 configured-unavailable + 发 typed redacted 诊断，禁止隐式凭据 fallback。
- reload 分类 `restart/hot/none`（config schema lookup 提供字段级 reloadKind）。

**→ Rust 建议**：config 用 `serde` + `figment`（分层：文件 + env + flag）+ `garde`/`validator` 校验。SecretRef 是枚举（内联 / env / 文件 / 外部 provider 如 1Password），解析结果用 owner 标记 + 降级状态。迁移器是一组"版本 N → N+1"的纯变换 + 备份。

## 13. 插件与扩展接缝

- **核心 plugin-agnostic**：核心不内置 plugin id/默认/策略，用 manifest/registry/capability 契约。plugin 只经 `openclaw/plugin-sdk/*`、manifest metadata、注入的 runtime helper、documented barrels 跨入核心。
- 两类：**code plugin**（运行时扩展：providers/channels/tools/hooks）/ **bundle plugin**（stable 外部面：skills/MCP/config，优先用）。
- manifest 声明资源（extensions/skills/prompts/themes，file 或 glob）；未列的回退到约定目录发现。
- 内置 bundled plugin 随核心 dist；外部官方 plugin 自持 package/deps，用 registry-aware facade-runtime。
- **可注册的接缝**：tools、providers、channels、hooks、compaction provider、context engine、memory（单槽）、speech、realtime voice、media 生成、web search/fetch、gateway RPC 方法（带 scope）。
- **Hook 系统**（agent loop 内 / gateway pipeline）：`before_model_resolve` / `before_prompt_build` / `before_agent_reply` / `agent_end` / `before/after_compaction` / `before/after_tool_call` / `before_install` / `tool_result_persist` / `message_received/sending/sent` / `session_start/end` / `gateway_start/stop`。决策语义：`before_tool_call {block:true}` 终态且停低优先级 handler，`{block:false}` 无操作不清除既有 block；`message_sending {cancel:true}` 同理。
- 进程稳定元数据（installs/manifests/catalogs/generated paths）：改动需重启或显式 owner reload/install/doctor。运行时热路径**不做**新鲜度轮询（stat/realpath/reread/hash），复用当前快照/发现/查找表。

**→ Rust 建议**：核心用 trait 定义所有扩展点。code plugin 在 Rust 里较难做成动态加载（无稳定 ABI）——可选：(a) 编译期 feature/静态注册（对官方 bundled 插件最省事）；(b) WASM 插件（`wasmtime` + component model，做 sandbox 接缝）；(c) 子进程 + MCP/JSON-RPC（最松耦合，对应 bundle plugin 与外部 harness）。Hook 用 trait 对象列表 + 优先级，决策语义按上面照搬。

## 14. 性能要点（Rust 重写重点）

原实现是"纯 TypeScript + promise，无外部依赖、无后台 worker 线程"。Rust 重写的性能杠杆：

1. **模型运行时代际快照**（§8）：`Arc` + `ArcSwap` 原子发布，run 零拷贝共享 auth/registry/catalog。TS 里靠不可变对象 + 引用，Rust 里是零成本。这是最大单点收益。
2. **热路径携带 prepared facts**：provider id、model ref、channel id、target、capability family、attachment class 在早期解析一次并向前传，**绝不**在请求时用宽泛 loader 重新发现。避免"用零散缓存修复重复发现"，而是把 canonical fact 前移。
3. **SQLite 单写线程 + WAL 并发读 + 同步提交事务**（§11）：rusqlite 同步写贴合"事务回调内不 await"约束，天然消除 async 事务的正确性坑；写队列 actor 序列化写，读连接池并发。
4. **Prompt cache 确定性排序**（§6）：maps/sets/registries/plugin lists/files/network results 在进模型 payload 前确定性排序，尽量保留旧 transcript 字节，最大化 provider prompt cache 命中。
5. **车道调度器**（§4）：tokio task + 信号量，per-session permit=1，全局车道 = CPU 并行度。无线程池争用。
6. **流式零拷贝**：SSE/delta 解析尽量 `Bytes` 切片；block chunker（min/max 边界 + 断点偏好 paragraph→newline→sentence→whitespace→hard，不破坏代码围栏）在字节层做。
7. **记忆 Lane 1 无模型调用**（§10）：纯 SQL + 向量预筛，是延迟敏感路径，用 `sqlite-vec`/LanceDB + 每步超时。
8. **事件广播按 scope 过滤**（§2）：每连接独立 seq，用 `broadcast` channel + 订阅端过滤，避免为每客户端复制全量事件。
9. **进程稳定元数据不轮询**（§13）：安装/manifest/catalog 快照化，热路径复用，改动才重建。
10. **可表示性约束**：用判别联合/封闭枚举表达状态（TS 里是 discriminated union），让"不可能的状态无法表示"，减少运行时分支与校验开销。

**架构级建议**：单二进制 + tokio；Gateway 是一组 actor（渠道、连接、lane 调度、SQLite 写队列、记忆、审批注册表）；共享只读快照用 `Arc`/`ArcSwap`，可变共享用细粒度 `Mutex`/`RwLock` 或 actor 消息；扩展点全部 trait；外部/不受信扩展走 WASM 或子进程边界。

## 附：几个必须照搬的正确性不变量

- 每主机一个 Gateway（网关锁）；每渠道一个会话。
- 首帧必须 connect，否则硬断开；事件不重放，gap 靠客户端刷新。
- side-effecting 方法必须幂等键去重。
- 一个会话同时只有一个活跃 run（会话车道 permit=1）。
- Transcript 写在同步事务内校验会话代际，stale run 不覆盖新代。
- SQLite 写事务回调内不 await / 不 return Promise。
- 拒绝比运行 build 新的 schema；迁移前向且一次性。
- 记忆 origin class 存 SQLite 列、写入端分类、绝不默认 owner；untrusted 内容永不自动注入 curated / prompt。
- provenance 无法判定 → 保守（untrusted/system）；SecretRef 未知归属 → fail-closed。
- `NO_REPLY` 静默 token 从出站过滤。
