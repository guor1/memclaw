# OpenClaw 功能点清单（Rust 重写参考）

> 目的：为用 Rust 从底层重写 OpenClaw 提供一份完整的功能盘点。
> 标注约定：**【必须】** = 构成一个可用产品的核心骨架，缺了就不成立；**【加分】** = 增强体验 / 覆盖更多场景，可分阶段实现或做成插件。
> 分析基于当前仓库（`openclaw` v2026.7.2，state schema 6 / agent schema 16）。

---

## 0. 一句话定位

OpenClaw = **一个常驻的多渠道 AI 网关（Gateway）**：单进程持有所有消息渠道连接（WhatsApp/Telegram/Slack/…），把入站消息路由到"智能体（agent）"运行时，通过 LLM + 工具执行产生动作与回复，并把结果流式回渠道。控制面（CLI / Web UI / macOS / 移动端节点）通过 WebSocket 协议连接同一网关。

产品是"助手"，Gateway 只是控制平面。核心保持 plugin-agnostic，可选能力尽量做成插件。

## 1. Gateway（网关 / 控制平面）

| 功能点 | 等级 | 说明 |
|---|---|---|
| 单进程长驻守护，持有全部渠道连接 | **【必须】** | 每主机一个 Gateway；是唯一开启 WhatsApp(Baileys) 会话的地方 |
| WebSocket 控制协议（req/res/event 三种帧） | **【必须】** | 见核心机制文档。首帧必须是 `connect`，否则硬断开 |
| 握手 + challenge nonce 签名 | **【必须】** | 设备身份签名（v3 绑定 platform/deviceFamily） |
| 鉴权模式 `none/token/password/trusted-proxy` | **【必须】** | 至少要有 token/password；`none` 仅限私有 ingress |
| 幂等键（side-effecting 方法 `send`/`agent`） | **【必须】** | 短期去重缓存，保证安全重试 |
| 角色/scope 模型（operator/node/worker + 6 个 operator scope） | **【必须】** | `operator.read/write/admin/approvals/pairing/talk.secrets` |
| 事件广播 + 按 scope 过滤 | **【必须】** | chat/agent/tool 需 `operator.read`；每连接独立 seq |
| 协议版本协商（minProtocol/maxProtocol，当前 v4，node 可 N-1） | 【加分】 | 起步可固定单版本 |
| 帧大小限制 + `payload.large` 诊断事件 | 【加分】 | 预握手 64KiB，握手后由 policy 决定 |
| HTTP 服务：Canvas host `/__openclaw__/canvas/`、A2UI | 【加分】 | 与 WS 同端口（默认 18789） |
| OpenAI/OpenResponses 兼容 HTTP API、tools-invoke HTTP API | 【加分】 | 让 OpenClaw 反过来当 provider/工具端点 |
| Cloud worker 协议（封闭 allowlist，SSH 隧道 loopback ingress） | 【加分】 | 云端执行主机，属高级特性 |
| TLS + 证书指纹 pinning | 【加分】 | 远程访问用 |
| 多网关 / 多租户托管 | 【加分】 | |
| 优雅挂起/恢复（suspend lease）、重启恢复（restart continuation） | 【加分】 | 更新后可续跑一轮 |
| health / heartbeat / tick 心跳事件 | **【必须】** | tick 保活，客户端据此判活 |
| 网关锁（单实例保证） | **【必须】** | 防止两个 Gateway 抢同一状态/会话 |

### 2.2 安全 / 门控

| 功能点 | 等级 | 说明 |
|---|---|---|
| DM allowlist + pairing（配对） | **【必须】** | 多用户下必须，否则串号 |
| 群组策略 `open/allowlist`，成员/群 allowlist | **【必须】** | |

### 2.3 支持的渠道清单

核心内置：**iMessage、Telegram、WebChat**（随核心安装）。

官方插件渠道（`openclaw plugins install @openclaw/<id>`）：
Discord、WhatsApp、Slack、Signal、Feishu(飞书)、Google Chat、IRC、LINE、Matrix、Mattermost、Microsoft Teams、Nextcloud Talk、Nostr、QQ Bot、Raft、Reef、SMS(Twilio)、Synology Chat、Tlon、Twitch、Voice Call、Zalo、Zalo Personal、ClickClack。

外部插件：WeChat(微信)、Yuanbao、Zalo ClawBot。

> **重写建议**：先实现 1~2 个渠道（WebChat + Telegram/Discord）跑通全链路，其余全部做成可插拔渠道插件。渠道抽象契约本身是**必须**，具体渠道大多是**加分**。

| `agent` / `agent.wait` RPC | **【必须】** | 立即返回 runId，wait 只等不停 run |
| 系统提示词组装（base + skills + bootstrap + 覆盖，含 promptMode full/minimal/none） | **【必须】** | |
| 工作区 bootstrap 注入（AGENTS.md/SOUL.md/USER.md/MEMORY.md，带字符预算截断） | **【必须】** | |
| Harness 系统：内置 `openclaw` 运行时 + 插件 harness（Codex 等） | **【必须（内置）/加分（外部 harness）】** | harness 选择策略 auto |

| 上下文引擎（可插拔：ingest/assemble/compact/afterTurn 四生命周期） | **【必须（legacy 内置）/加分（插件引擎）】** | 默认 legacy 引擎即够用 |
| 多智能体路由（多 agent × 多账号 × bindings 最具体优先） | 【加分】 | 单 agent 模式是默认，多 agent 是增强 |
| 子智能体 / swarm / 委派（sessions_spawn，push 式完成通知） | 【加分】 | VISION 明确不做经理套经理的层级框架 |
| 目标追踪（goal 工具） | 【加分】 | |
| 停止/转向命令（/stop、/steer、/queue interrupt） | **【必须】** | 用户必须能打断 |

## 21. 重写优先级建议（MVP → 完整）

**Phase 1（骨架 / 必须）**
1. SQLite 存储层（state DB + per-agent DB + 迁移 + 同步事务）
2. 配置加载 + secrets + doctor 迁移
3. Gateway WS 协议（握手/鉴权/scope/幂等/事件）+ health/tick
4. Agent 循环（队列车道 + steer/interrupt + lifecycle/assistant/tool 流 + 超时）
5. Provider 抽象（OpenAI + Anthropic 兼容）+ 模型目录 + failover + retry
6. 系统提示词组装 + bootstrap 注入
7. Compaction（自动 + 手动）
8. 核心工具集（exec + 文件 + web_fetch + web_search + ask_user + message）
9. Exec 审批 + 工具策略 + 权限模式
10. 会话路由 + DM scope + 重置
11. Skills 加载 + 注入
12. 一个渠道（WebChat）+ 一个真实渠道（Telegram/Discord）
13. CLI：onboard/doctor/gateway/agent/models/channels/config/status
14. 记忆分层最小版（MEMORY.md/USER.md 注入 + memory_search + provenance）
15. Audit ledger

**Phase 2（加分）**
插件系统 + SDK、多 agent 路由、更多渠道、沙箱、MCP、流式预览/块流、cron/tasks/hooks、媒体、prompt caching 深度优化。

**Phase 3（生态 / 平台）**
节点与设备、Talk/实时语音、Control UI/Canvas、Dreaming/standing intents、cloud worker、伴生 App、OTel/Prometheus、ClawHub。

> **Rust 性能重点**（详见核心机制文档第 12 节）：模型运行时代际快照、prompt cache 确定性排序、SQLite 同步写事务 + 连接池、车道调度器（tokio 任务）、热路径避免重复发现（携带 prepared facts）、流式分块的零拷贝。
