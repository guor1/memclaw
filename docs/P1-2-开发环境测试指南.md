# P1-2 开发环境测试指南

> 适用场景：本地开发环境（Rust workspace），未安装 `oc` 二进制，想验证 standing intent 功能。
> 真机测试用例见 [09-P1-2-standing-intent测试用例.md](09-P1-2-standing-intent测试用例.md)。

---

## 前置准备

### 1. 确认代码已编译通过

```bash
cd c:\dev\workspace\MyClaw
cargo build --release
```

编译后**只有一个**二进制 `target/release/oc.exe`（在 [oc-cli/Cargo.toml](../crates/oc-cli/Cargo.toml)
定义 `[[bin]] name = "oc"`）。所有功能都在它里面，按子命令区分：

| 命令 | 作用 |
|---|---|
| `oc`（无子命令） | 连 daemon 进 TUI 对话 |
| `oc serve` | 启动 daemon（常驻进程） |
| `oc onboard` | 初始化配置 |
| `oc intent add/list/rm` | 待办管理 |

`oc-tui` 是**库 crate**（被 oc-cli 依赖），不单独产出二进制——TUI 通过 `oc`（无子命令）进入。

### 2. 准备隔离测试环境

```bash
# Windows PowerShell
$env:OC_HOME = "C:\temp\oc-test-p1-2"
mkdir $env:OC_HOME

# 或者 Git Bash
export OC_HOME=/c/temp/oc-test-p1-2
mkdir -p $OC_HOME
```

### 3. 初始化配置

```bash
target/release/oc.exe onboard
```

这会在 `$OC_HOME` 下生成：
- `config.toml`（需手动配置 API key）
- `soul/SOUL.md` 等文件

### 4. 配置模型 API key

编辑 `$OC_HOME/config.toml`，设置真实的 API key：

```toml
[[models]]
alias = "default"
provider = "openai"
model = "deepseek-chat"
hosting = "cloud"
base_url = "https://api.deepseek.com/v1"
api_key = { env = "DEEPSEEK_API_KEY" }  # 或改成 { inline = "sk-xxxx" }
```

如果用环境变量：
```bash
# PowerShell
$env:DEEPSEEK_API_KEY = "sk-your-key-here"

# Git Bash
export DEEPSEEK_API_KEY="sk-your-key-here"
```

## 测试流程（TC-P1-2a + TC-P1-2b 核心场景）

### 终端 A：启动 daemon

```bash
# 确保 OC_HOME 已设置
target/release/oc.exe serve
```

看到 `[info] oc daemon 启动` 说明成功。日志会输出到 `$OC_HOME/logs/oc.log.*`。

### 终端 B：添加待办（CLI 操作）

```bash
# 添加一条待办
target/release/oc.exe intent add "带转换插头" 出差 德国

# 输出示例：
# 已添加话题待办：intent-01936e92-xxxx-xxxx-xxxx-xxxxxxxxxxxx
```

**解释**：
- `"带转换插头"` = 提醒正文（触发后注入的内容）
- `出差 德国` = 两个关键词（命中任一即触发）

查看已添加的待办：
```bash
target/release/oc.exe intent list

# 输出示例：
# intent-01936e92-xxx  触发词:[出差 德国]  已提醒:0/3  上次:从未  «带转换插头»
```

**字段含义**：
- `已提醒:0/3` = 已触发 0 次，budget 上限 3 次
- `上次:从未` = 尚未触发过（或显示 unix 时间戳）

### 终端 C：启动 TUI 对话

```bash
target/release/oc.exe  # 无子命令 → 进 TUI
```

TUI 会连接到 daemon（通过命名管道或 Unix socket）。

## TC-P1-2b：话题命中 → 模型自然提起

### 输入消息（在 TUI 里）

```
我下周要去德国出差，应该准备点什么？
```

**关键词命中**：消息包含「德国」和「出差」，触发 `intent_scan`。

### 预期行为

1. **daemon 日志**（终端 A 或 `tail -f $OC_HOME/logs/oc.log.*`）：
   ```
   [INFO] standing intent：触发注入 intent=intent-01936e92-xxx fired=1
   ```

2. **模型回复**（TUI 里）：
   模型应该**自然提到**「转换插头」，例如：
   > 去德国出差需要准备：护照、签证、欧元现金、**别忘了带转换插头**（德国用欧标插座）、...

   **注意**：模型不会生硬地说「待办提醒：带转换插头」，而是**融入回答**里。

3. **验证记账**（终端 B）：
   ```bash
   target/release/oc.exe intent list
   
   # 输出变化：
   # intent-01936e92-xxx  触发词:[出差 德国]  已提醒:1/3  上次:1735689600  «带转换插头»
   #                                          ^^^        ^^^^^^^^^^^
   #                                          计数+1      unix时间戳
   ```

### 如果模型没提到插头？

**可能原因**：
1. **上下文太长**：bootstrap 注入的内容被"淹没"（可能性较低，默认注入靠前）。
2. **模型判断不合适**：模型认为当前语境不该提（属模型决策，非 bug）。
3. **注入失败**：检查 daemon 日志是否有 `standing intent：触发注入`。

**排查**：
```bash
# 检查日志
grep -i "standing intent" $OC_HOME/logs/oc.log.*

# 如果有 "触发注入"，说明注入成功了，模型选择不提属正常（可换更强引导）
# 如果没有，说明预筛没命中（检查关键词是否写对）
```

## TC-P1-2c：无关话题 → 不触发


## TC-P1-2g：含空格关键词整条匹配（回归 bug）

### 添加含空格关键词的待办

```bash
target/release/oc.exe intent add "预定机票" "business trip" "international travel"
```

**注意**：`"business trip"` 和 `"international travel"` 各是**一个**关键词（带引号）。

验证关键词往返：
```bash
target/release/oc.exe intent list

# 应显示：
# 触发词:[business trip international travel]
#          ^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^^^^
#          两条，非四条（business / trip / international / travel）
```

### TUI 测试：只含部分词 → 不触发

```
I have a trip next week.
```

**预期**：模型**不提**「预定机票」（只有 `trip`，不含完整的 `business trip`）。

### TUI 测试：完整短语 → 触发

```
I have a business trip next week.
```

**预期**：模型**应提**「预定机票」（完整匹配 `business trip`）。

## TC-P1-2d：cooldown 抑制二次触发

### 添加短 cooldown 待办

```bash
target/release/oc.exe intent add "记得喝水" 健康 --cooldown-secs=30
```

### TUI 第一次触发

```
怎样保持健康？
```

**预期**：模型提到「喝水」，`intent list` 显示 `已提醒:1/3`。

### TUI 第二次（<30 秒内）

```
健康生活方式还包括什么？
```

**预期**：
- 模型**不再提**「喝水」（cooldown 内静默）
- daemon 日志：`standing intent：命中但拒绝触发 reason=Cooldown`
- `intent list` 计数**仍为 1**（未二次记账）

### 等 31 秒后再试

```
健康的定义是什么？
```

**预期**：模型可以再次提「喝水」（cooldown 过期），计数抬到 2。

---

## TC-P1-2e：budget 用尽后静默

### 添加 budget=2 的待办

```bash
target/release/oc.exe intent add "检查邮箱" 工作 --budget=2 --cooldown-secs=1
```

### TUI 触发 3 次（每次间隔 >1 秒）

1. `今天工作有什么安排？` → 模型提「检查邮箱」，计数 1/2
2. `工作中如何提高效率？` → 模型再提「检查邮箱」，计数 2/2（用尽）
3. `工作压力大怎么办？` → 模型**不再提**「检查邮箱」，计数仍为 2

daemon 日志第 3 次：`reason=BudgetExhausted`

## TC-P1-2h：每轮注入上限

### 添加 5 条同关键词待办

```bash
target/release/oc.exe intent add "检查进度" 项目 --budget=10
target/release/oc.exe intent add "更新文档" 项目 --budget=10
target/release/oc.exe intent add "通知客户" 项目 --budget=10
target/release/oc.exe intent add "备份代码" 项目 --budget=10
target/release/oc.exe intent add "开会讨论" 项目 --budget=10
```

### TUI 一次性触发

```
今天项目有什么要做的？
```

**预期**：
- 模型**最多提到 3 项**（配置 `intent_max_per_turn=3`）
- daemon 日志：`达每轮注入上限，其余顺延`
- `intent list` 看到**恰好 3 条** `已提醒` 从 0 抬到 1，另外 2 条仍为 0

## 查看日志（排查问题）

```bash
# 实时查看日志（PowerShell）
Get-Content $env:OC_HOME\logs\oc.log.* -Wait -Tail 50

# Git Bash
tail -f $OC_HOME/logs/oc.log.*

# 过滤 standing intent 相关
grep -i "standing intent" $OC_HOME/logs/oc.log.*
```

**关键日志**：
- `standing intent：触发注入 intent=<id> fired=<n>` → 成功触发
- `standing intent：命中但拒绝触发 reason=Cooldown|BudgetExhausted|...` → anti-nagging 生效
- `standing intent：已过期，跳过` → 过期不触发
- `达每轮注入上限，其余顺延` → 每轮上限生效
